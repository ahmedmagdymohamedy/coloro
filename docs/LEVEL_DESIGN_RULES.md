# Coloro — Level Creation Rules

The single source of truth for building level packs. The generator is
`tool/gen_levels.dart`; the solvability gate is
`test/stall_diagnostic_test.dart`. **Never ship levels without running the
gate.**

## 1. The mechanic these rules serve

Docked bottles drink **only the bottom edge**: for each column, just the
lowest remaining pixel is reachable, taken one at a time, deepest row
first, swept left → right. A bottle holds its slot until it fills up. A
bottle whose color is nowhere on the bottom edge **starves**; when all 4
slots hold starving bottles the machine jams and the level is lost.

Everything below follows from that.

## 2. What a level is

- A **full-square PNG** in `assets/levels/`, named `<n>.png`. 1 image
  pixel = 1 board cell.
- An entry in `assets/levels/levels.json` recording *everything* about it:

```json
"70.png": {
  "name": "Bloom",        // motif, shown in the UI
  "gridSize": 24,          // cells per side (== the PNG's pixel size)
  "maxColors": 9,          // palette cap handed to the quantizer
  "hard": false,           // every 5th level is hard
  "colors": 9,             // colors actually present after quantization
  "cells": 576,            // total pixels to drink
  "churn": 0.58,           // vertical interleaving (see §4)
  "shuffleWindow": 7,      // tray scramble strength (see §5)
  "dealSeed": 68429,       // the proven-solvable shuffle
  "bottles": 60            // bottles the level deals
}
```

## 3. Hard rules (never violate)

| Rule | Value |
|---|---|
| Colors per level | **minimum 5**, maximum 10 |
| Color separation | ≥ 56 weighted-RGB apart (the runtime quantizer merges below ~52, which would silently collapse the palette) |
| Column coverage | every color must appear in **≥ 55% of columns** — a color confined to a few columns starves its bottle and hostages a slot |
| Grid size | 15 … 40 cells per side |
| Board | full square — every cell is content |
| Bottle size | capped at ~⅓ of that color's total, so bottles pop often and slots keep turning over |
| Solvability | every shipped deal must pass `BottleFactory.isDealSolvable` |

## 4. Difficulty dial #1 — VERTICAL CHURN

How often the color changes walking up a column. `[A,A,A,B,B,B]` needs two
bottles in sequence; `[A,B,A,B,A,B]` forces constant swapping against only
4 slots. Measured as the fraction of vertical neighbour pairs that differ,
and the generator **forces** the board to reach the level's target:

| Track | Churn |
|---|---|
| Normal 1 → 240 | 0.30 → 0.58 |
| Hard 1 → 60 | 0.45 → 0.70 |

Sources of churn: the two-band sky, ground seam, shaded motifs, secondary
motifs at other heights, checker rows (hard levels), and `_bandBackground`,
which re-tints ONLY sky/ground cells in horizontal bands at whichever band
period lands closest to the target — difficulty as design, not noise.

## 5. Difficulty dial #2 — TRAY SHUFFLE

The tray is dealt from a proven-feasible base order, then permuted within
sliding windows of `shuffleWindow` bottles. Window 1 = perfectly sorted
(the bottle you need is always at a front — trivial). Larger windows push
the needed bottle deeper into a column, so the player must park bottles in
slots and keep one breathing.

| Track | Window |
|---|---|
| Normal 1 → 240 | 2 → 9 |
| Hard 1 → 60 | 4 → 12 |

## 6. Solvability — the witness

A shuffle can make a level unwinnable, so nothing ships unproven.
`BottleFactory.isDealSolvable` runs a **slot-constrained search over the
real game**: only the 4 column fronts are reachable, 4 slots, bottles
hostage until full, drinking simulated exactly as the controller does it
(the board state compresses to per-column drunk counts, which makes it
memoizable). The generator tries the strongest shuffle first and walks
down — window, then fresh scenes, then a lower color target — and records
the first `(shuffleWindow, dealSeed)` pair the solver beats. The runtime
reproduces that exact deal from those two numbers.

**The slot count is campaign-wide**: `GameController.slotCount` and
`BottleFactory.slotCount` must agree, and changing it invalidates every
level's solvability proof — regenerate the whole campaign after touching
it.

## 7. Campaign structure (300 levels)

- **240 normal** + **60 hard**, interleaved **4 normal : 1 hard** (every
  5th level is hard).
- Grid: normal 15 → 39, hard 20 → 40.
- Colors: normal 5 → 9, hard 7 → 10 (eased only if unsolvable).

## 8. Generator structures (`tool/gen_levels.dart`)

- `LevelSpec.forLevel(n)` — all ramps in one place.
- `Grid` — `fill`, `shade`, `outline`, `plus`, `ring`, `checkerRow`.
- `Zone` — places a motif in a sub-region (secondary motifs).
- `Palette` — sky pair + ground + **accents generated by farthest-point
  sampling** over hue × lightness × saturation, so they are guaranteed
  mutually distinct.
- `MotifDef(name, draw, tier)` — 17 shaded motifs in 3 tiers; the pool
  opens up as levels progress.
- `buildScene` — sky → ground → scenery → motif → minis → hard structures
  → scatter → sparkles → fairness passes.
- Deterministic: seeds derive from the level number.

## 9. Shipping checklist

1. Edit `tool/gen_levels.dart` (new motif → add a `MotifDef`; new theme →
   add a `Palette`).
2. `dart run tool/gen_levels.dart` — regenerates every PNG + `levels.json`.
   It refuses to ship a level it cannot prove solvable.
3. `flutter test test/stall_diagnostic_test.dart` — re-proves the shipped
   deals against the art on disk and checks the ramps. **Never weaken or
   delete this gate.**
4. `flutter test` — full suite green.
5. Spot-check ~10 level thumbnails across the range.
